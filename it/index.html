Progetti scelti

#work · padding clamp(72px, 11vh, 150px)

  1. Ruolo attuale2025 - oggi

    1. I prodotti di un’azienda della formazione costruiti come un unico ecosistema dietro un solo login: gestionale, marketplace, ticketing, timesheet.

      Il problema
      Strumenti separati, login separati. Ogni nuovo prodotto voleva dire un altro database utenti.
      Cosa ho fatto
      Ho progettato l’architettura e scritto gran parte del codice. Un authorization server emette token OIDC che portano solo l’identità; ogni prodotto tiene i propri ruoli e decide chi entra.
      Sotto il cofano
      Spring Boot 4 su Java 25, Vaadin 25 con viste Flow e React, Spring Authorization Server, JPA e Flyway su MySQL, checkout Stripe embedded. I rilasci sono tag git: l’immagine va su GHCR e si ridistribuisce con docker compose. Circa 1.000 commit su cinque repository, primo committer in ognuno.
      1. Vaadin 25
      2. Spring Boot · Java 25
      3. Authorization Server · OIDC
      4. JPA · Flyway
      5. MySQL

      • Uno scraper Playwright in Java, porting di un prototipo Python, che alimenta MySQL.
      • Un client desktop Electron per strumenti interni.
      • Script Python che validano dati Excel e PDF per il processo di conformità di un cliente enterprise.
      • Un sito aziendale in Next.js.

  2. Ruolo precedente2022 - 2025

    1. Una piattaforma di project management: app mobile e web app con gantt, timeline, automazioni sui task e Microsoft 365.

      Il problema
      Team che pianificano da telefono e desktop, con viste che fogli di calcolo e chat non potevano dare.
      Cosa ho fatto
      Ero autore principale di entrambi i client: l’app Flutter e la web app Next.js, fino al gantt, all’editor rich-text, all’export PDF e all’accesso Microsoft 365.
      Sotto il cofano
      Flutter con flutter_bloc e dio, Next.js con TipTap e react-pdf, MSAL e Microsoft Graph, Firestore e Cloud Functions su Node. Oltre 1.000 commit come autore principale.
      1. Flutter
      2. Next.js
      3. Cloud Functions
      4. Firestore
      5. Microsoft Graph

      • Un’app social geolocalizzata per un cliente sotto NDA: Expo e Firebase, ricerca di prossimità con geohash, clustering su mappa, chat vincolata all’abbonamento.
      • Un sito aziendale in Next.js.

  3. Personali2024 - 2026

    1. Un’app nativa per organizzare viaggi di gruppo: votare la destinazione, costruire l’itinerario, dividere le spese. Costruita due volte, apposta.

      Il problema
      I viaggi di gruppo muoiono nelle chat: nessuno decide la destinazione, le spese si perdono, il piano vive nella testa di uno solo.
      Cosa ho fatto
      Ero primo committer della v1, fatta in sei nel 2025 (Angular, Ionic, Express, Prisma su Postgres). Poi ho scritto un piano tecnico e l’ho ricostruita da solo su Expo: voto della destinazione, conguaglio automatico delle spese, itinerario su mappa e calendario, chat realtime.
      Sotto il cofano
      Expo SDK 56 con expo-router e NativeWind, Zustand, Zod, react-native-maps. Cloud Functions v2 su Node 20. Rules Firestore testate sull’emulatore, unit test sulla divisione spese.
      1. Expo 56 · expo-router
      2. Cloud Functions v2
      3. Firestore · rules testate
      4. Firebase europe-west1

    2. Un gioco musicale su carte stampate: inquadri il QR, parte la traccia su Spotify, indovini prima degli altri.

      Il problema
      I quiz musicali hanno bisogno di un conduttore con una playlist. Volevo una scatola di carte che facesse girare il gioco da sola.
      Cosa ho fatto
      Un’app React Native per scansione, riproduzione e punteggi. Uno script Python costruisce il mazzo da Spotify e dipinge un gradiente radiale dentro ogni QR, perché sembri un mazzo e non un foglio di codici a barre.
      Sotto il cofano
      Expo SDK 51, expo-camera, Zustand, NativeWind, Spotify Web API. Generatore di carte in Python con qrcode e Pillow.
      1. Expo 51 · camera
      2. Spotify Web API
      3. Python · qrcode · Pillow
